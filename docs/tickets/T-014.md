## Findings (implementer)
Method: Chrome headless (--dump-dom --enable-logging=stderr --virtual-time-budget), Node 16, direct URL loads of /portfolio /projects /history /contact-me /nope /index. Click-through is the same as a direct load because MenuBar/Sidebar use plain `<a href>` (full page load).
Reproduced (app code): NOTHING. No CONSOLE errors, no failed requests, no 404 assets, no blank DOM, no error overlay, in either mode.
- Production build via `serve -s build -l 3998`: all 6 URLs render their h1/h2 (Projects, "Education" h2 on /history, "Contact information"); unknown path and /index fall to Portfolio.
- Dev server (Node 16, PORT 3999): all 6 render; only console output is `[HMR] Waiting for update signal from WDS...`, the React DevTools hint, and the lint warning `./src/components/Sidebar.js Line 106:21: Anchors must have content and the content must be accessible by a screen reader  jsx-a11y/anchor-has-content` (a warning, not an error; not fixed, out of scope).
- Pre-paint theme script, PageTracker (analytics off without env), Redirects, ThemeToggle: no exceptions.
Reproduced (environment), two real causes:
1. Static host without SPA rewrite (best match to the report: the home page works, Projects/Contact/History fail). Serving `build/` with a host that has no fallback (python http.server): `/` 200, `/portfolio` 404, `/projects` 404, `/history` 404, `/contact-me` 404 (body "Error code: 404 ... File not found"). Menu links are full reloads, so clicking from home hits this. Render ignores `public/_redirects` (Netlify format); a Render static site needs a rewrite rule `/* -> /index.html` set in the dashboard or a render.yaml. The repo had neither. Fixed: added `/render.yaml` (Blueprint with the rewrite); if the live service was created by hand, the same rule must be added in the dashboard (Redirects/Rewrites, Source `/*`, Destination `/index.html`, Action Rewrite). I cannot see the live service, so this is the most likely cause, not confirmed on the live site.
2. Node 25 (the user's session default): `npm start` fails on every page with `Error: error:0308010C:digital envelope routines::unsupported at new Hash (node:internal/crypto/hash:103:19) ... webpack/lib/util/createHash.js:135:53` (react-scripts 4 / webpack 4 hash md4; `nvm use 16` per .nvmrc fixes it). Not changed: `--openssl-legacy-provider` is rejected by Node 16, so a package.json workaround would break the verified Node 16 path.
Other likely user-side causes if the live site still errors: stale cached build, old service worker (none registered here).
Files changed: /render.yaml (new), /src/hosting.test.js (new), this ticket.
Contract as built: render.yaml static service, build `npm run build`, publish `build`, rewrite `/*` -> `/index.html`, GENERATE_SOURCEMAP=false. No dependency, no env var added.
Edge cases: Blueprint only applies if the service is created from it; dashboard rule is equivalent.
Known gaps: regression test checks the config text only (cannot execute Render); no app-code defect found so no router test added. Verify: tests 130 pass (Node 16), `npm run -s build` exits 0.
